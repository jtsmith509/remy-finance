## How to run the verification (on the Mac mini)

```bash
cd remy-finance && uv sync
uv run python scripts/verify_thetadata.py            # default: SPY, AAPL, KO; last 5 sessions
uv run python scripts/verify_thetadata.py --date 2026-09-15 --symbols SPY,AAPL,KO   # window around a dividend
```

The script writes `data/verification/r0_1_<UTC>.{md,json}` (git-ignored); the JSON includes every request and response sample. It sends no credentials; the Terminal holds the login. The checks: 0 connectivity; 1–5 the contract items; X1 rates and index; X2 concurrency; X3 storage per snapshot. Its logic is unit-tested offline against a mocked Terminal (`tests/unit/test_verify_thetadata_script.py`).

Test underlyings: **SPY** (the ETF), **AAPL** (the megacap) and **KO** (the dividend payer; choose `--date` so the window covers a KO ex-date).

### 1. Bid/ask sizes: expected PASS
Quote fields: `bid, bid_size, bid_exchange, bid_condition, ask, ask_size, ask_exchange, ask_condition, timestamp`, both historical and live. The script checks two things: that the fields are present, and what fraction of two-sided quotes have positive sizes. Sizes are NBBO displayed sizes in contracts, which is what FILL-1 needs.

### 2. Underlying prices: expected PARTIAL (the main gap besides dividends)
- **What we have:** greeks endpoints such as `option/history/greeks/first_order`, `option/snapshot/greeks/*` and `option/history/greeks/eod` return `underlying_price` and `underlying_timestamp`. That gives one price per timestamp, and it is not documented whether it is a last trade or a mid. History needs a specific expiration (no `*`), so it takes one extra small request per underlying per snapshot. Stock EOD (FREE) gives `close` and the closing NBBO each day.
- **What we lack:** the **underlying bid/ask and sizes at 10:00 / 15:45**. These are required for:
  - `UnderlyingQuote` in `MarketState` (handoff §4).
  - ASSIGN-1 forced closes, where stock closes at the underlying bid or ask (DR-0009).
  - The universe and movegen moneyness reference. That works with a single price, so it isn't a blocker.
- **Options:**
  - **(a)** Upgrade Stock to **Value**. That gives historical NBBO at time of day (replay), but live stock quotes on Value are **15-minute delayed**. A prospective snapshot would then carry a stale underlying quote, which is unacceptable for the live board unless it's labelled.
  - **(b)** Upgrade Stock to **Standard**. That gives real-time Nasdaq Basic plus history. Note that Nasdaq Basic is not the consolidated NBBO.
  - **(c)** Stay on FREE. Use the greeks `underlying_price` as the board's underlying price, and approximate the stock bid/ask for ASSIGN-1 closes conservatively, for example `underlying_price ± max(0.01, k·price)`. This changes a handoff rule, so it would need a DR and Josh's approval.
- **Recommendation:** (b) if the cost is acceptable; otherwise (c) with an explicit DR. Also confirm in the live run whether the snapshot greeks `underlying_price` is real-time on Options Standard.

### 3. Dividends and corporate actions: expected FAIL, so a supplementary source is needed
No endpoint exists; the script probes the plausible paths and records the 404 or 410 responses. The only dividend input in ThetaData is the `annual_dividend` *parameter* on greeks requests. ASSIGN-1's dividend rule needs the **ex-date, amount and declaration time** for each dividend. Corporate actions such as splits, mergers and special dividends change option deliverables, and contracts with non-standard deliverables must be excluded (handoff §4).

**Recommended supplementary sources** (to be chosen in a new DR):
- **Dividends:** a provider whose records include a `declaration_date`. Examples are Polygon.io / Massive reference dividends and Nasdaq's dividend history. Conservative `public_time` rule: **the declaration date at 16:00 ET**, and the dividend is usable from the next snapshot. For an audit-grade alternative, use SEC EDGAR 8-K and press-release acceptance timestamps, which are exact but expensive to parse.
- **Corporate actions and adjusted options:** OCC Information Memos list contract adjustments and new deliverables with publication dates. As a cheaper complement, flag any contract whose OSI root carries a numeric suffix (for example `AAPL1`) as non-standard.
- The dividend window in the test (KO) still matters for one reason: to confirm that ThetaData's quote stream shows nothing unusual across an ex-date. Strikes are not adjusted for ordinary dividends.

### 4. Time-of-day retrieval: expected PASS
- **Request:** `option/at_time/quote` with `expiration=*`, `start_date`/`end_date`, `time_of_day` in `HH:MM:SS.SSS` ET and `max_dte=60`. The docs warn that sub-minute times with `expiration=*` "may hang". Our times (10:00, 10:05, 15:45, 15:50, 12:45, 12:50) are all on minute boundaries.
- **Look-ahead check:** the script measures, per row, how old the quote is relative to the requested time. It **fails** the check if any row is stamped after the requested time.
- **Timestamps:** returned timestamps are ET wall-clock times with no offset. The adapter (R0.3) must localize them to America/New_York and then convert to UTC.

### 5. Expired contracts: expected PASS
Expired expirations and strikes are listed, and quotes for an expiration about 30 or more days past are fetched at 15:45 a week before expiry. `list/contracts/quote?date=` is the clean way to rebuild "the chain as it existed on date D" for the point-in-time universe and replay.

## Other findings

| Topic | Finding |
|---|---|
| Must the Terminal run on the Mac mini? | **Yes.** It's a Java 21+ jar (`ThetaTerminalv3.jar`, with credentials in `creds.txt` or `--creds-file`). It serves REST only on `127.0.0.1:25503`; ThetaData says not to expose that port. All jobs must run on the same host. R1.6 should add a `launchd` agent that keeps the Terminal running, and `doctor` should check it. The jar auto-updates, so record the Terminal version in every snapshot manifest. |
| Rate limits | ThetaData caps **concurrent requests per tier**, not request rate: documented as Value 2 and Standard 4. Third-party sources say Free is 1, Pro is 8, and the cap is account-wide at your highest tier. Excess requests queue. Check X2 measures wall-clock time at 1, 2, 4 and 8 parallel requests. **Plan:** a client-side semaphore of 4. |
| Error behaviour | Errors return a non-200 status with a plain-text body. Expected codes are 403 or 471 (permission), 472 (no data), 473/400 (bad params), 474 (disconnected) and 410 (v2 path). The adapter maps these to typed errors, and treats "no data" as an empty result, never as a crash. |
| Rates (DR-0011) | `rate/history/eod` (FREE) with symbols `SOFR` and `TREASURY_M1` … `TREASURY_Y30`; daily values. The units (percent or decimal) and publication time must be read from the live sample. Expected: **DR-0011 can use ThetaData**, with `public_time` set conservatively to the next business day at 09:30 ET. |
| Official close (EXP-1, DR-0010) | Stock EOD (FREE) `close` is ThetaData's own EOD report, generated at 17:15 ET. It's not documented whether it equals the primary-listing **official closing auction price**. Spot-check a few dates against the exchange's official close in the live run. |
| Universe ranking (DR-0004) | 20-day option volume per root is available from option EOD data (`option/history/eod?expiration=*`, one day per request). That is about 80 names × 20 days = 1,600 small requests to bootstrap, then 80 per day. Fine. |
| Index | Index EOD (e.g. SPX) is FREE; intraday index prices need Value+. Not needed in R0–R1, because the universe is stocks and ETFs. |
| Greeks | Options Standard includes first-order greeks and IV, plus EOD greeks with all orders. MKT-1 (R1.4) computes its own IVs from quotes, so ThetaData greeks are not used for ranking. They could serve as a cross-check, and as the source of `underlying_price`. |

## Storage estimate (to be replaced by check X3)

These are first-principles numbers; the script measures the real ones.
- **Rows per underlying (≤ 60 DTE, all strikes):**
  - Large index ETFs (SPY, QQQ) have daily expirations: about 30 expirations × 300–600 strikes × 2 rights ≈ 20–35k rows.
  - Typical liquid single names: about 8–10 expirations × 50–150 strikes × 2 ≈ 1–3k rows.
- **Weighted mean across 50 names:** about 3–5k rows per underlying.
- **Bytes:** with about 13 fields per row and Parquet with zstd at roughly 25–40 bytes per row, that is about **100–200 kB per underlying**.
- **Per 50-name snapshot:** about **5–10 MB**. Adding the execution quotes (DR-0003) gives 4 chain captures per day, or **about 20–40 MB per day and 5–10 GB per year**.
  - Restricting stored strikes to ±25% (DR-0008) would cut this by roughly half.
  - Underlying quotes, rates and dividends are negligible by comparison.
- **Implication:** comfortably outside git, as DR-0012 already decides. A 1 TB external drive holds decades. Replay snapshots for a month cost about 1 GB.

## Known limitations of this memo
- No live request was made from this session. Every verdict is documentation-based until the script runs on the Mac mini.
- The third-party sources (concurrency numbers, the rate endpoint path, 403 on Free) are lower-confidence than the official OpenAPI spec.
- The `underlying_price` semantics (last trade or mid; real-time or delayed on snapshot) are undocumented and must be read from the live output.
